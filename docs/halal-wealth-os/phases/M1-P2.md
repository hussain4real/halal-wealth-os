# M1-P2: Atomic posting, transfers and reversals

Status: ACCEPTED by the human owner; see [acceptance](../runs/M1-P2-acceptance.md). Depends on owner-accepted M1-P1. Original
canonical prose and private golden fixtures remain outside this public checkout.
Build a minimal balanced journal behind simple personal transaction forms.
Make cash movements auditable, atomic, idempotent and reproducible.

## Tasks

- M1-P2-T1: Journal entries and postings support pending/posted/reversed semantics and balance per currency.
- M1-P2-T2: One posting service handles income, expense, opening balances and same-currency transfers.
- M1-P2-T3: Transactions, owner-scoped unique retry keys and database locking/constraints protect concurrent requests.
- M1-P2-T4: Correct posted entries through linked reversal and replacement; preserve original posted values.
- M1-P2-T5: Provide owner-scoped entry, history and receipt-reference views.
- M1-P2-T6: Publish domain events after the outer commit and document downstream retry behavior.

## Acceptance

- M1-P2-AC1: Every posted journal balances per currency; an unbalanced request persists no legs.
- M1-P2-AC2: An owned same-currency cash transfer preserves net worth and household income/expense totals.
- M1-P2-AC3: Concurrent requests using one key create one logical transaction with a stable result.
- M1-P2-AC4: Injected failure rolls back all legs; reversal restores the prior balance and retains original history.
- M1-P2-AC5: Server-side owner and retry enforcement includes direct submissions.
