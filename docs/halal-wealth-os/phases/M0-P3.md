# M0-P3: Identity, ownership and application shell

Status: local READY_FOR_REVIEW candidate; not accepted. Depends on human-accepted M0-P2.
Canonical phase text restored from the original plan v1.1 dated 10 October 2026,
as supplied by the manager. Source identifiers and raw retrieval evidence remain
in private owner evidence. Existing roadmap task and acceptance IDs are preserved.

Build the private application shell and enforce ownership before storing
financial records. Filament is a restricted administration surface, not a second
public frontend.

Goal: Ensure every user-facing and administrative path has an explicit
authorization boundary.

## Tasks

- M0-P3-T1: Configure private owner onboarding, login/logout, password reset and rate limits using the selected auth stack.
- M0-P3-T2: Define owner-scoped policies and query conventions; add two synthetic users to isolation tests.
- M0-P3-T3: Build the Inertia navigation shell, accessible form/error patterns, empty states and currency display component.
- M0-P3-T4: Restrict Filament access to an explicit admin capability and test direct resource URLs.
- M0-P3-T5: Add security/audit event conventions with sensitive-value redaction and actor attribution.
- M0-P3-T6: Document session settings and the two-factor requirement that must pass before personal production use.

## Acceptance

- M0-P3-AC1: Anonymous access to protected routes is denied; public self-registration is disabled unless explicitly approved.
- M0-P3-AC2: User B cannot read or mutate User A data through route IDs, submitted owner IDs or admin resources.
- M0-P3-AC3: Login/logout, reset and rate limiting pass automated tests; no production secrets appear in logs.
- M0-P3-AC4: Core shell navigation works by keyboard and displays validation failures accessibly.
- M0-P3-AC5: Admin access cannot be gained by changing frontend state or ordinary profile fields.

## Deliverables and verification

Private shell; auth policies; protected admin panel; isolation and session tests.
Verify authentication, owner isolation, admin denial, validation and browser
navigation. All global invariants and verification contracts apply; map each AC
to observed evidence. Use server-side authorization everywhere; never rely on
hidden UI controls.

Excluded: Public signup, subscriptions, household sharing and enterprise tenancy.
Preserve full starter authentication features while making onboarding private.
No financial implementation, live credentials, real user provisioning,
deployment, infrastructure/security-setting changes, merge or later phase.
Only accepted-stack dependencies with verified official compatible releases may
be added. Retain PHP 8.5.x, local Pest TIA and full uncached verification.

Complete only M0-P3 and stop at READY_FOR_REVIEW or a documented blocker. Use
at most six bounded implementation/verification cycles and an independent
source-read-only reviewer. Milestone independent review follows individual
human acceptance of every M0 phase; it is not phase acceptance.
