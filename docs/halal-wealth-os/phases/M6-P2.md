# M6-P2 - Market and FX provider adapters

**Milestone:** M6 - Controlled integrations and notifications
**Dependencies:** M6-P1. When crossing milestones, the previous milestone gate must also be accepted.
**Initial status:** PLANNED. Owner authorization and dependency acceptance determine readiness.

## Description

Add authorized data sources behind provider interfaces while preserving manual observations and deterministic tests.

## Goal

Refresh valuations safely without making the application depend on provider uptime.

## Task checklist

- [ ] **M6-P2-T1** Define price/FX provider contracts and source licensing, coverage and rate-limit requirements.
- [ ] **M6-P2-T2** Implement one approved provider per data type; support manual fallback and mock transport in tests.
- [ ] **M6-P2-T3** Normalize symbol identifiers, quote currency, timestamps and effective dates with stale-data thresholds.
- [ ] **M6-P2-T4** Add scheduled refresh jobs, bounded retry/backoff and per-provider run logs without sensitive data.
- [ ] **M6-P2-T5** Protect ingestion from duplicate runs, malformed numbers and impossible/future observations.
- [ ] **M6-P2-T6** Keep prior observations and reproduce valuations using their original version references.

## Acceptance criteria

- [ ] **M6-P2-AC1** Provider timeout/rate-limit behavior leaves the last observation intact and visibly stale where appropriate.
- [ ] **M6-P2-AC2** Repeated or concurrent refreshes do not create duplicate effective observations or duplicate downstream actions.
- [ ] **M6-P2-AC3** A wrong-currency, invalid-number or future-dated response is rejected with an attributable ingestion error.
- [ ] **M6-P2-AC4** No external API is needed for deterministic CI; live credentials are never required to mark mocked unit tests passed.
- [ ] **M6-P2-AC5** Provider selection has an approved access/licensing record; live connectivity is reported separately as verified or blocked.

## Deliverables

Provider interfaces; approved adapters; refresh jobs; outage/fallback evidence.

## Verification emphasis

Contract tests, timeout/429 handling, payload validation, idempotence and stale-data fallback.

All applicable global invariants and the verification contract also apply. Use the run template to record observed evidence; a checklist tick alone is not proof.

## Scope exclusions

Unlicensed feeds, high-frequency trading, vendor lock-in and historical-data fabrication.
